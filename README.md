## How the automation works

```
GitHub API → GitHub Actions (scheduled every 6h) → Python (scripts/fetch_stats.py)
           → docs/data/stats.json → docs/index.html charts (Chart.js)
```

- `scripts/fetch_stats.py` — pulls real repo/language/PR/issue/activity data from the GitHub REST API and writes `docs/data/stats.json`. No numbers are invented; anything unavailable is left `null`.
- `scripts/generate_hero_svg.py` — regenerates the animated banner above using the latest synced totals.
- `.github/workflows/update-stats.yml` — runs both scripts on a 6-hour schedule (and on push) and commits the results.
- "Live" here means *automatically re-synced on a schedule*, not instantaneous — see the note in the dashboard's GitHub Intelligence section for the exact last-sync time.

Contribution-calendar data specifically requires a personal access token with `read:user` scope (the default Actions token can't read another account's calendar) — add one as a repo secret named `GH_PAT` to enable it; otherwise that field is simply omitted rather than faked.
